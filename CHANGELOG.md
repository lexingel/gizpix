# Changelog

## 0.3.0 (unreleased)
- `ABOUT.md` rewritten for the current tool: pixart (drawing from code, figures in 8 directions), effects moved to GizVFX, and a new section on what we learned about paperdoll layers from AI sprites. New `RESEARCH_PAPERDOLL.md` (the full research note, 8 figures in `images/paperdoll/`).
- pixart: `cands` (2-3 candidates on one numbered sheet), `pick` (records the user's pick in knowledge/picks.jsonl), `calibrate` (how often the style distance agreed with the picks); `look --style` follows the drawing's size bucket; `profiles` re-measures style_profiles.json; the skill now ends every asset with 2-3 candidates along one axis.
- New package `pixart`: draw any pixel art from code with the craft rules built in. An indexed canvas where every pixel is (ramp, tone): on-grid shapes as masks (rect, oval, poly, pixel-perfect line and curve, blob, text grid), hue-shifted ramps from one base colour, one light for the whole picture, form shading (flat, ball, tube, puff, slab, grad, bands) with clean tone clusters, cast shadows between parts, a 1 px light-aware outline (selout / dark / black), careful inner anti-aliasing, checker dither, palette merge and fixed palettes, pixel lettering (5x7 with Turkish letters, 3x5; bold, gradient, bevel, bands, chrome, shadow, fixed width), animation export through the existing sheet code, a review sheet (1x on three backgrounds, silhouette, greyscale, palette) and a lint on top of `pixel_lint` (colour budget, near-duplicates, pure black, edge, thin parts, ramp steps, tone specks). 11 worked recipes, `pixart new / examples / lint / guide / selftest`.
- `pixart` figures: `pixart.rig` (skeletons by joint angle: `humanoid`, `quadruped`, own `Rig`, `chain`, `turn`, `far`, grounding that bobs the body), `pixart.poses` (14 actions as key poses with milliseconds and tags: idle walk run slash thrust smash stab bow punch kick shoot block hurt cast), canvas shapes `limb`, `chain`, `membrane`, `bow`, `crescent`, `silhouette`, `strip(sil=True)`; recipe `knight`; samples from the blind tests (archer, dragon).
- `pixart` directions: `rig.solve(pose, direction="S" | degrees, tilt=0.45)` projects one side-plane pose to any facing in a top-down 3/4 view (depth order, per-bone depth, sideways offsets for shoulders and hips), `mannequin8` with `paint=` hooks, `face_point`, `body_width`, `sheet(rows, path)`; recipe `adventurer8` (walk and attacks in 8 directions, nothing mirrored).
- `pixart` game-asset helpers, from a side-by-side test against real game art: `oval(angle=)`, `ring`, tapered `curve(w1=)`, `fill(form="glow")` for things lit from inside, `texture`, `seam`, `links`, `rim`, `outline(rim=)`, `palette_of`; commands `pixart measure` (read a reference: palette, outline, light, grid view) and `pixart compare` (side by side). Fixed: a hand-placed tone past the ramp's end crashed the lint; re-toned texture raised a false "thin parts" flag.
- `pixart look FILES --ref ART`: numbers for the hand-made look (orphans, small clusters, run length, tone step...) and the distance from reference art; `pixart compare` adds a difference map for two same-size images; `pixart/exemplars/` = accepted game-asset scripts to start from.
- `pixart/knowledge/styles.md` + `pixelblog_*.md`: styles and genres from the Slynyrd Pixelblog series, posts 1-64 (size ladder per genre, projections, construction recipes, timings); `ramp9(hue)` builds the series' 9-swatch ramp.
- `pixart/knowledge/`: study notes from the user's weapon reference collection (294 images, 4 PDFs: stances and key poses per weapon, slash effects, armour, 8 directions) and web research (animation timing, clean-up, sub-pixel, materials, subject plans), with an index; digest in KNOWLEDGE.md sections 14-17.
- `pixart/KNOWLEDGE.md`: the pixel-art craft rules distilled from four books and two web tutorials (Pixel Logic, Make Your Own Pixel Art, Pixel Secrets, Arcade Game Typography, Derek Yu, Tsugumo), each marked as done by the engine, measured by the lint, or left to the artist.
- pixart: reference collection hooks: `pixart refs` (query `PixTools/refs/index.csv` by style / subject / size / view / material / tier, spread over packs, contact sheet, copy for `look --ref`; packs whose licence forbids AI use are always skipped), `pixart look --style Sxx` (distance from a style profile), `knowledge/style_profiles.json` (look numbers of 23 styles from the hand-made refs) and `knowledge/references.md`. The user's AI style cards were cleaned with Gizpix (speck_fix, fill_pinholes, outline thinning, glints kept), graded and stored as tier `ai`.
- pixart: from the exam agents' wishes: house family `iron` (dark weapon/armour metal), `pipe(closed=True)` rings, `ellipse_pts()`, `spaced()` (rivets, studs), `segments()` (plates/lames), `flip()`, `outline(lines={ramp: colour})`; CLI `measure --rows` and a clear message when `lint` gets a script.
- pixart: `Canvas.pipe()` (tapered, shaded bar along a curve, returns its own u/v space); fixes: `grow(m, 0)` / `shrink(m, 0)` returned the whole canvas, 3-digit hex colours crashed.
- pixart: `house(name, n)` house-palette ramps measured from the game's item icons (`house_palette.json`: 11 colour families, 7 tones, the game's line colour and tone shares; shaded fills take their tone borders from the shares).
- pixart: `Canvas.tidy(bands=False)` clean-up pass (tone specks, 1 px bumps on tone borders, optional hairline-band dissolve; hand pixels and the silhouette stay); lint numbers `spur_px` (flagged) and `band_px`.

## 0.2.0
- `pixfx` (effects, recipes and the painted styles) moved out into its own tool, GizVFX (https://github.com/lexingel/gizvfx); the entries below about it are kept as history.
- Painted: glows fall off in the pixel renderer's bands (soft edges), watercolor has more body and colour on dark grounds. Beam colours across the width match the pixel beam.
- Painted, the last small differences from the pixel frames: `rim`, a true gradient across a `beam` with a white-hot line, core-shaded dots (coin-burst is gold again), thicker speed lines, a glow with the pixel renderer's flat first step (shield-bubble, bomb-fuse), crossing-line sparkles for `star`, more body in watercolor.
- Painted: native `include`; a white-hot beam core; glows are added as light over everything beneath (orbs and beams are as bright as in the pixel version); the ramp colours follow the pixel steps; smear trails use 14 copies. After a frame-by-frame review of all 31 recipes against the pixel frames.
- Painted: native smooth `funnel`, `bolt`, `rays`, `poly` (only `include` still goes through the smooth upscale); brighter `beam`, banded `ring`, thicker `star` and `bolt` after a frame-by-frame review against the pixel frames.
- Painted: native smooth `particles`, `blob`, `star`, `orbit` and `beam` (the particle and blob simulations are shared with the pixel renderer: its output is byte-identical to before), and `smear`, `erode`, `outline` in the painted version. Only rays, bolt, poly, funnel and include still go through the smooth upscale.
- `pixfx painted` now works for every shipped recipe: layers without a native smooth version are drawn as pixels and smoothly upscaled, glow stays soft in every style; painted ring/glow follow `squash`, `arc` and the pixel ring geometry, discs are shaded; `lineart` keeps thin parts as one line; `glitch` no longer wraps rows or darkens by alpha.
- Painted: `glitch` takes `--intensity` and `--hold`; new style `lineart` (thin glowing outline); `brush` takes `head` (where it is fattest); `chalk` is stronger. `melee/claw-scratch` and `impacts/ink-burst` use pointed strokes, `melee/speed-dash` has a diagonal hatch.
- Painted style `glitch` (sliced rows, RGB split, scanlines, new every frame). Pixel `splat` gets an outline, no white middle and a gloss spot; pixel `speedlines` are wedges; `linocut` and `chalk` keep thin lines.
- New layers `burst` (comic star burst), `speedlines` (radial or parallel) and `splat` (blob, droplets, drips), and recipes `impacts/pop-burst`, `impacts/paint-splat`, `melee/speed-dash`; both renderers draw them. Painted styles `linocut` and `stencil`.
- `pixfx painted --style ink|watercolor|comic|chalk`: four looks for the painted version of one recipe (watercolor wet edges and granulation, comic flat colour with outline, chalk broken coverage).
- New layers `brush` (ink stroke with bristle lanes that dry out; the head runs past the path so one-shots end empty), `hatch` (parallel-line shading) and `halftone` (comic dots), and three recipes that use them: `melee/ink-slash`, `melee/claw-scratch`, `impacts/ink-burst`.
- `pixfx painted ID`: the same recipe drawn smooth at 4x with a real alpha channel (layers brush, hatch, halftone, glow, disc, ring). Technique ideas from reading cloveric/claude-drawing (MIT); no code copied.
- Colour limiting counts strongly saturated pixels 3x, so a small accent (a red spark in a blue effect) keeps its own palette slot instead of being merged into a neighbour. Idea from reading cloveric/claude-drawing (MIT); no code copied.
- Found by the second blind test: a full-turn `poly` rotation now closes a loop (points are rounded), `poly` `anchor: base`, particle `lob` (parabola that lands at its spawn height), `blob` `stagger` ignored in loops. The handout lists what breaks a loop seam.
- Recipe language: `poly` (crystals, rocks, shards), `stamp` (your own PNG up to 32x32 from the recipe's folder), `include` (an effect inside an effect, 2 deep). Every recipe is now limited (40 layers, canvas 8 to 256, particles 400) and `pixfx import FILE.json` validates, renders, reports and keeps a copy in `~/.gizpix/recipes`. New recipe: crystal eruption.
- Recipe language: curved paths (`at` with 3+ points) and `spin`, per-step `ease` lists, `blob` modes `flame` and `ring` (`drift`, `stagger`), particle shapes `bubble` and `shard`, a whole-effect `style` pass (outline, rim, shadow) and palette roles (`"@role"`). New recipes: curving orb, dust ring; soul wisp (a real flame silhouette) and acid splash (flat puddle, popping bubbles) redrawn.
- Recipe language: `smear` (a fading, shrinking trail of any moving layer), `outline`/`rim`/`erode` on every layer, `beam` drawn as one distance field (`core`), `funnel` `profile`/`bend`/`ripple`; `arc` `trail` renamed `tail`. `pixfx check --report`: mesh dithering, flat colour, lone pixels, empty frames, motion pops, with a fix per flag. New recipe: comet; tornado, soul wisp, vampire drain and smite redrawn.
- Recipe language: `funnel` layer (swirling column), particle `target` + `curve` (fly from a spawn area to a point), layer `wobble` (snaking, swaying). Tornado, soul wisp, vampire drain and portal redrawn with them; `pixfx palettes` lists the palette names.
- Recipe language: `blob` `erode` (dissolve from the edge), `glow`/`rays` `squash`, particle `shape: star`. Smoke puff redrawn with them.
- `pixfx` output cleanup, found by running `pixel_lint` over every effect: the additive glow used to make 120+ near-duplicate colours (torch) and half-transparent pixels. Every effect is now limited to one shared palette of 24 colours by default (`-o colors=N`, 0 = off), and `-o hard=true` makes glow dithered on/off with no half-transparent pixels. Recipe language: values may have more than two keys (`[0, 1, 0]`), options can be scaled (`"$reach*0.5"`), `blob` takes `lit`, `bolt` takes `rim`, `beam` takes `shade: flat`; a ring thinner than a pixel no longer draws as dots. The poison-cloud, shield-bubble, fire-breath, energy-orb and smoke-puff recipes were redrawn after a review.
- `pixfx` recipes: describe an effect as a JSON file of layers (glow, disc, ring, star, particles, blob, bolt, rays, orbit, beam, arc) with animated values, options and a palette, and render it like any other effect (`pixfx render my.json`). `pixfx schema` lists every layer and key, `pixfx recipe ID` prints a shipped recipe to copy, and mistakes are one-line errors naming the closest correct key. Twenty-one recipes ship (vampire drain, tornado, smite, bomb fuse, portal, acid splash, soul wisp: written blind by an agent that had only the handout, all passing `pixfx check`; energy orb, poison cloud, level up, teleport, blood hit, fire breath, smoke puff, lightning strike, shield bubble, ice spear, meteor impact, fire wall, summoning circle, coin burst); `pixfx check` covers them like the Python effects.
- `pixfx`: code-drawn pixel effects (13: torch, fireball, small explosion, hit spark, shockwave, lightning bolt, frost nova, heal, magic circle, coin sparkle, slash, rain, snow). Two buffers (pixels and additive light), effects as functions of time with a seeded generator, 22 palettes or your own, GIF + sprite sheet + JSON export, `pixfx check` (deterministic, loops close, one-shots end empty, nothing cropped).
- `pix_snap` recognises exact whole-number upscales first (they come back pixel for pixel); `speck_fix` reports pixels it kept and suggests a `--rare` value; `pixel_lint` has `odd_px` and an "odd-coloured pixels" flag (advisory); README notes on `--rare` and Windows globs.
- Fixed GIF flicker in `pixdraw` animations: transparency index 0 was forced, so on scenes with an opaque ground colour the ground was flagged transparent and colours flashed between frames. All frames now share one palette and transparency is used only when a frame has transparent pixels; `pixdraw selftest` decodes the GIFs and compares them with their source frames. The README village GIF was rebuilt (its per-frame 64-colour palettes also flashed).
- `ABOUT.md`: a plain-language overview with pictures (`images/about/`, rebuilt by `experiments/evidence/make_about.py`).
- Licensing made explicit: code AGPL-3.0-or-later with a commercial licence on request, documentation CC BY 4.0, evidence pictures CC0 (`LICENSE-DOCS`); `CONTRIBUTING.md` (contributions under MIT so the code can be dual-licensed), a pull-request template, SPDX headers on every Python file.
- `experiments/evidence/make_evidence.py` and `images/evidence/`: pictures of the layer, `--drop-parts`, dark-skin failure and clean-up tools on real generated frames; `MEASUREMENTS.md` rewritten around them.
- `pip install` support: the `gizpix` command (`pip install git+https://github.com/lexingel/gizpix.git`).
- Web interface: a `Choose folder…` button opens the operating system's own folder dialog (Browse stays as a fallback); Pack shows `folder/*.png` in its command; `#demo-recolor` and `#demo-pack` captures.
- Sample frames are now drawn from code (`samples/make_samples.py`), so they share Gizpix's licence; the earlier AI-generated frames are no longer bundled.
- `python gizpix.py ui`: a local web interface (Python standard library server on 127.0.0.1, plain HTML/CSS/JS, no build step, self-hosted open fonts) for the four jobs: clean & measure, cut outfit layer, draw buildings, recolour & pack. Results are staged first and saved only on request, always to a new folder; each result shows its exact command; previews use whole-number nearest-neighbour zoom; frames are shown as exposure-sheet columns.
- `ui/design_options/`: the six design sketches that were scored before the interface was built.
- Web interface self-test added to `selftest_all.py`.
